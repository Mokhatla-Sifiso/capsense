# ADR-001 Rendering approach

| Field        | Value                                                                                                                                                                                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Status       | **Accepted** · Muzi · 2026-10-21 (rev. 2: data path, QA-B4)                                                                                                                                                                                                                                                   |
| Context      | Responsive dashboard over a fixed, read-only API (7 GET endpoints). Front-end role (MR-05), production-grade (MR-01), one Dockerfile (MR-02)                                                                                                                                                                  |
| Options      | A Next.js 16 App Router · B Vite 8 SPA + TanStack Router (see `adr-options.md`)                                                                                                                                                                                                                               |
| **Decision** | **A: Next.js 16, App Router, TypeScript strict**                                                                                                                                                                                                                                                              |
| Data path    | **First render:** Server Components call `queryClient.prefetchQuery` reading the **seed module directly** (no HTTP self-call), then pass the cache to the client via `HydrationBoundary`. **After hydration:** client components use the same query keys and fetch the route handlers over HTTP (ADR-002/003) |
| Rationale    | react.dev recommends starting with a framework, with Next.js App Router listed first. 41.1M weekly npm downloads; 58.6% usage (State of JS 2025). Prefetch + hydrate is TanStack Query's documented server-rendering pattern                                                                                  |
| Consequences | + Fast first paint with real data (NFR-P1); one container (ADR-006). − Server-side code ships in a front-end submission (MR-05): it's limited to mock handlers and prefetch, and the README explains it. The client/server boundary must be explicit (`"use client"` only on interactive islands)             |
| Trace        | G-01–G-07 (problem-definition); C-01; NFR-P1, NFR-P2; ADR-002, ADR-003, ADR-006                                                                                                                                                                                                                               |
